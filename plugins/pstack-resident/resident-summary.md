- Nontrivial change, architecture decision, "are we sure?" → pstack-how.
- Code crossing a function boundary → pstack-architect. Parallel fan-out → pstack-swarm. Bakeoffs → pstack-arena. Contested design → pstack-interrogate.
- Any code → name the data shape first (pstack-principle-model-the-domain).
- Any prose, replies included → pstack-unslop. Docs, PR descriptions, commit messages → pstack-technical-writing. Before review → pstack-no-comments. Reporting a measured number → pstack-benchmark-checklist.
- Before asking the human a "which approach" question: if running code could answer it (behavior, timing, layout, perf), sketch it via the Prototype playbook and let the result decide; only genuine product or preference calls go to the human.
- Nontrivial multi-step → write the throughput checkpoint (Feature playbook step 3).
- PR-status requests ("check on PR X") → the Babysit playbook. Landing a green stack → the Shipping playbook. Long or autonomous work → a pstack-show-me-your-work decision trail.
